# codex-unfence

macOS 上的 Codex 浏览器站点状态补丁。一条命令安装，一条命令检查，一条命令卸载。

当浏览器访问仅因站点状态中的 `feature_status.agent === true` 被阻止时，补丁在选定的请求／响应通道中提供 `agent: false` 的响应副本。原请求、判定器、缓存逻辑和其他响应字段保留。用户授权、企业策略、登录和网站自身的限制仍然有效。

需要 **macOS、Node.js ≥22.13.0 和 npm／npx**。

> 当前版本 `0.2.0` 尚未发布到公共 npm registry。下面是发布后的使用入口；发布前可按[本地运行](#本地运行)生成安装包，通过同样的命令使用。

## 安装补丁

```bash
npx codex-unfence install
```

工具发现安装并检查兼容性。只有一个安装时自动选中；多个安装时交互选择。自行完全退出对应桌面应用及相关浏览器服务，核对目标、支持依据和影响，输入 `yes` 后写入。其他输入或 EOF 取消。

**补丁会修改应用签名资源，使严格签名校验失败，系统可能拒绝加载修改后的应用。** 工具不会重新签名、提权、关闭系统验证或替你退出、启动应用。

成功后核对报告，再手动重新打开应用。重复安装会识别已安装状态。

## 检查兼容性与当前状态

```bash
npx codex-unfence check
```

一次列出所有发现的安装，分别显示：

- 实际代码是否受支持。
- 当前是原版、已安装补丁、未完成操作还是冲突。
- 能否安装，以及进程、权限或恢复资料等阻断原因。

检查只读，不创建备份或恢复存储，无需交互确认。默认查找 `/Applications` 和操作系统账户的 `~/Applications`。

指定其他路径，或只检查一个安装：

```bash
npx codex-unfence check --app /Applications/ChatGPT.app
```

请使用实际应用路径；产品名称不决定应用包名。需要结构化输出时追加 `--json`。JSON 使用 `schemaVersion: 1`，`data.inspections` 包含所有检查结果；只有单一安装时，`data.inspection` 才提供该项结果。

| 检查退出码 | 含义 |
| --- | --- |
| `0` | 检查完成，所有发现的安装结构受支持且无冲突。仍需查看写入条件。 |
| `1` | 运行失败，包括没有发现安装、读取失败或无法核实进程状态。 |
| `2` | 参数错误。 |
| `3` | 存在不受支持的安装。 |
| `4` | 存在文件、路径或恢复资料冲突。 |

多个安装的结果按运行失败、冲突、不兼容、成功的顺序聚合。应用仍运行或目录不可写等写入阻断单独报告；退出码 `0` 不表示可以安装。JSON 的 `writeReadiness`、`blockers` 和 `allowedActions` 描述写入条件，其中 `apply`／`restore` 分别对应 `install`／`uninstall`。

## 卸载补丁

```bash
npx codex-unfence uninstall
```

自行退出应用和相关服务，核对目标并确认。工具使用可信原始内容和事务记录恢复文件；重复卸载不会再次修改已恢复的文件。完成后再手动打开应用。

`install` 和 `uninstall` 表示安装或撤销插件文件补丁，不会全局安装或移除 npm 工具。两者均支持 `--app <应用绝对路径>`，要求真实交互终端，不接受 `--json`。`npx` 的包获取确认不代替补丁操作确认。

## 操作中断或失败

上次操作未完成时，重新运行 `install` 或 `uninstall` 即可。工具会先询问是否回滚中断操作，回到该操作开始前的状态，再重新检查并确认本次安装或卸载。

回滚和后续操作分别确认。拒绝恢复时保留现场；回滚失败或文件发生未知变化时停止，不覆盖冲突内容。回滚成功后取消后续动作，已经完成的恢复仍然保留；请核对报告中的当前文件状态。可以先运行 `check` 查看诊断。

| 状态 | 含义 |
| --- | --- |
| `original` | 原始文件，当前未安装补丁。 |
| `tool-applied` | 磁盘文件具有可信补丁记录。 |
| `incompatible` | 当前结构不受支持。 |
| `incomplete` | 存在未完成操作；安装／卸载会引导恢复。 |
| `conflict` | 文件或恢复资料校验失败，需保留现场并处理诊断。 |

兼容性根据实际代码的有限结构模式判断，不由桌面版本号决定。未知模式或多个候选通道会被拒绝。引导会展示结构依据及宿主、依赖行为假设。

`Runtime: not-verified` 表示尚未验证应用已加载补丁或网站访问成功。磁盘补丁成功不等于运行验证通过，也不会立即清除应用已有的站点状态缓存。

## 更新应用与保留资料

更新桌面应用前，先卸载补丁；更新后重新检查。不要用旧备份覆盖升级后的未知文件。

工具在操作系统账户主目录保存恢复资料：

- `~/Library/Application Support/codex-unfence/`：原文、补丁副本、目标记录、密钥与事务备份。
- `~/.codex-unfence/target-leases/`：账户级协调历史。

这些资料独立于仓库、调用目录和 npm 缓存，不受 `HOME`／XDG 环境变量覆盖影响。请保留匹配版本的工具及完整恢复资料，不要移动存储或手工删除记录、密钥与锁。

恢复目标文件不会自动验证整个应用签名或网站访问。

## 本地运行

仓库统一使用 `package.json` 中固定版本的 pnpm 管理依赖、构建和打包。发布前，从当前仓库生成 `.tgz`。在仓库目录安装依赖：

```bash
pnpm install --frozen-lockfile --ignore-scripts
```

打包会自动构建：

```bash
pnpm pack
```

用产物的绝对路径替代 registry 包即可；后续把 `install` 换成 `check` 或 `uninstall`：

```bash
npx --offline --package "$PWD/codex-unfence-0.2.0.tgz" codex-unfence install
```

请保留本地包，以便清理 npm 缓存后仍可获取相同工具版本。

## 开发

使用明确的比较基线运行统一检查：

```bash
pnpm run check --base HEAD
```

维护代码全部使用 TypeScript，包括测试、预加载夹具、工程脚本和 ESLint 配置。`dist/` 是公开 CLI 的编译产物；`.build/` 是测试与工具的独立编译产物，两者均不作为源码提交。插件 JavaScript 语法样本是文本数据，不经 TypeScript 编译。开发使用 pnpm；npm／npx 保留为用户获取工具与分发兼容性验收入口。

检查包括空白、全部 TypeScript 类型检查、lint、构建和测试；未跟踪新文件不进入空白差异检查。测试使用合成源码、临时文件系统和本地安装包，不需要真实 Codex 安装。

无子命令时进入交互引导；`apply`／`restore`／`status`／`recover` 保留为托管高级入口，使用同一账户恢复资料，不接受 `--plan`／`--store`。完整用法见 CLI 帮助：

```bash
npx codex-unfence --help
```
