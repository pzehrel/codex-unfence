# 仅改写选定 JSON 结果中的站点状态字段

2026-10-27，用户再次明确：补丁仅修改 `feature_status.agent`，其他请求、响应接口和数据必须透传。旧包装器只提供 `ok` 和 `json()`，因此对共享运输函数和额外 Response 接口的拒绝源于包装器自身限制，偏离此要求。

新配方在已定位的站点状态响应 `await response.json(...)` 之后调整解析结果，仅将普通 JSON 数据中严格等于 `true` 的 `feature_status.agent` 改为 `false`，其他字段保留；不替换 Response 对象，不改变原请求、参数、接收者或其他响应方法。无关调用继续取得原始响应，即使其 JSON 恰好包含同名字段也不受影响；因此不再要求运输函数专用或响应仅使用 `ok/json`。仍需确认端点来源、选定 JSON 结果进入 `feature_status` 消费以及唯一的修改位置，无法定位时停止。

用户随后要求从实际源码独立确认补丁是否存在。检测比较完整版本 2 包装器的语法结构，并验证仅移除这一处包装后，站点状态 JSON 分析重新定位到相同位置；忽略纯排版差异，不把注释、字符串、改写过的包装器或重复嵌套当作正常安装。源码检测与恢复记录校验分别输出，记录丢失不抹去源码安装事实，也不据此授权自动卸载或重复安装。

本决定取代 ADR 0006 中替换 fetch await 表达式与限制响应接口的约束。新配方版本为 2，旧配方版本 1 的恢复材料继续按已保存字节恢复，不以新配方重算或覆盖旧备份；结构检查与真实运行生效仍分别报告。
