# Spec：基于结构兼容性的 Codex 浏览器补丁 CLI

## Problem Statement

当前工具是针对单个本机快照的 Python 验证脚本。它同时依赖固定版本目录、完整文件哈希和含压缩变量名的精确字节片段，导致无关格式变化、重新压缩或应用更新都会使补丁失效。用户无法区分“结构已变化，需要重新适配”和“仅文件内容不同，但补丁逻辑仍然适用”。

工具缺少可安装的项目交付形态、独立于本机 Codex 的测试及 CI。现有异常回滚无法处理强制终止后的多文件混合状态，也没有明确的自动化输出协议。用户需要一个能解释兼容性、可审阅、可恢复的插件文件补丁工具，而不是每次更新后人工修改字符串的脚本。

## Solution

交付一个支持 macOS 的 Node.js + TypeScript 命令行工具。它枚举浏览器插件工件，以 AST、作用域绑定和站点状态消费关系判断结构兼容性，生成可审阅方案，再按用户明确选择应用或恢复补丁。

补丁只在浏览器工具的站点状态消费点，把传给原判定器的响应副本中的 agent 禁止标志固定为 false。保留请求及其他响应字段，不扩大到用户授权、企业策略或其他安全判断。侧栏评论模式属于独立范围。

工具支持多版本发现、稳定 JSON 诊断、操作锁、持久事务记录及中断回滚。文件状态与运行时有效性分开报告。首版提供本地可安装的 npm 包，自动化验证不依赖真实 Codex 安装。

## User Stories

1. 作为 macOS 用户，我希望通过标准 npm CLI 安装方式使用工具，以便不再手动运行零散脚本。
2. 作为用户，我希望检测默认位置及显式指定位置的插件，以便适应不同的本机安装布局。
3. 作为用户，我希望看到所有发现的 browser/chrome 插件版本及实际路径，以便明确知道哪些工件可被操作。
4. 作为用户，我希望版本号只作为说明信息，以便无关版本变化不会自动阻止结构仍兼容的补丁。
5. 作为用户，我希望函数和局部变量改名、引号与空白变化不会破坏识别，以便适应常见重新压缩结果。
6. 作为用户，我希望工具验证站点状态来源、响应对象和 agent 禁止判定的关联，以便不会修改无关的相似函数。
7. 作为用户，我希望结构不支持时获得具体诊断，以便区分解析失败、缺少证据和控制流变化。
8. 作为用户，我希望出现多个候选时工具停止，以便不会由工具猜测应修改哪一处代码。
9. 作为用户，我希望只读检测不修改插件，以便先评估兼容性。
10. 作为用户，我希望在应用前查看目标、证据、局部差异及前后哈希，以便审阅实际修改。
11. 作为用户，我希望明确选择单个、多个人工指定的目标或全部兼容目标，以便控制修改范围。
12. 作为用户，我希望工具不把目录名最大的版本当成正在使用的版本，以便不会形成错误的运行时结论。
13. 作为用户，我希望准备方案保留原始内容和补丁内容，以便后续校验和恢复都有依据。
14. 作为用户，我希望准备后目标被升级或修改时应用失败，以便不会覆盖新内容。

17. 作为用户，我希望其他用户授权和企业策略仍按原流程处理，以便工具的作用范围明确。
18. 作为用户，我希望状态查询区分原始、已应用本工具补丁、不兼容、冲突及未完成事务，以便知道下一步能做什么。
19. 作为用户，我希望重复应用或恢复可以识别目标状态，以便避免重复修改。
20. 作为用户，我希望恢复使用已验证的备份，并保护后续外部修改，以便回退不会丢失其他变更。
21. 作为用户，我希望同时操作多个插件前完成全部预检，以便一个已知冲突不会造成部分写入。
22. 作为用户，我希望并发运行受到操作锁约束，以便多个工具实例不会交错写入。
23. 作为用户，我希望工具中途被终止后能识别未完成事务，以便下次运行能恢复而非重新猜测状态。
24. 作为用户，我希望显式恢复把事务回滚到操作前状态，以便工具不会在我不知情时继续应用。
25. 作为用户，我希望恢复遇到未知内容时保留现场并报告，以便应用升级或人工修改不会被覆盖。
26. 作为用户，我希望工具检测到相关进程运行时停止写入并列出信息，以便由我自行退出应用或工具进程。
27. 作为用户，我希望工具不自动结束进程，以便正在运行的工作不会被中断。
28. 作为自动化调用者，我希望稳定的 JSON 结果和可区分的非零退出码，以便可靠处理参数错误、不兼容、冲突和运行失败。
29. 作为用户，我希望文件修改、真实样本兼容和真实运行有效性分别报告，以便不会把文件哈希通过当成网站操作成功。

## Implementation Decisions

- 正式实现使用 Node.js + TypeScript，建立最低运行版本声明、依赖锁定、构建、类型检查、静态检查、测试和 CI。现有 Python 分析工具保留为研究资料，旧补丁脚本不作为新 CLI 的正式实现。
- 首版只支持 macOS。安装发现与补丁分析分离，为其他平台适配保留边界，但首版不承诺其正确性。
- 分为安装发现、纯源码补丁分析、事务管理和命令入口四个职责边界。避免把各层细节暴露成大量内部公共接口；主要行为由 CLI 对外提供。
- 安装发现枚举 browser/chrome 工件，返回实际路径及版本元数据。版本号与已知整文件哈希都不决定兼容性，也不用于推断当前运行版本。
- 纯源码补丁分析只接收源文本并返回分析结果及变换方案，不执行被分析源码，不依赖当前机器安装。适配范围是明确且有限的 AST 模式。
- 结构识别验证站点状态来源、响应对象、agent 为 true 时禁止的判定语义，以及消费链的作用域绑定关系。压缩名称和局部标识符不作为匹配依据；字段名称等领域语义属于证据。
- 对无法证明的关联、超出模式的控制流、解析失败、零候选或多个候选返回不兼容诊断，不退回宽松字符串替换。新增模式需要相应正反样例和审阅。
- AST 用于定位与验证；变换按目标表达式源码区间局部替换，不重新打印整个 bundle。只在本地消费点构造响应副本，将 agent 标志固定为 false，保留原始响应、其他字段及请求逻辑；输出再次进行语法解析。
- CLI 提供 detect、prepare、apply、status、restore、recover。检测默认只读，准备仅生成本地方案；写操作必须有明确的目标或方案。
- prepare 支持明确指定目标和全部兼容目标；方案含目标身份、结构证据、局部差异、前后哈希及原始/补丁后工件。方案生成失败时不得出现可被当作完整方案使用的产物。
- 哈希用于准备与应用之间的工件身份校验、写前写后校验、外部修改检测和恢复验证，不用作新版本准入白名单。
- apply 在写入前验证全部目标、方案及备份。任何目标已被外部修改时停止。重复操作按已知状态处理，不将未知修改误认成本工具补丁。
- status 区分未修改、已应用本工具补丁、不兼容、冲突和未完成事务。仅凭发现类似补丁形态而没有可信操作记录，不声明是本工具应用。
- 写操作使用操作锁、持久事务记录和逐文件原子替换。先记录必要恢复信息，再执行写入；持久记录覆盖写入与状态更新之间被终止的窗口。多文件操作不宣称具有单个文件系统原子交换的性质。
- recover 显式回滚到当前事务操作前状态，不自动继续应用。发现未完成事务时阻止普通写操作，先处理恢复。
- restore 与 recover 都验证当前内容和已知前后状态；遇到升级、其他修改或无法解释的内容时保留现场并报告冲突，不覆盖未知数据。
- apply、restore、recover 在写前检查相关 Codex 应用与浏览器工具进程。发现运行中的相关进程时停止并提供信息，不自动终止进程；检测局限需要明确报告。
- 人类可读输出与 JSON 共用同一结果模型。定义结构化诊断及退出码契约，区分参数错误、不兼容、冲突和运行失败。
- 文件状态与运行时状态分别报告。进程退出重启、旧模块和缓存重新加载、宿主完整性行为都属于真实运行验证，文件补丁成功不能替代这些证据。
- 首版交付可本地构建、安装及打包的 npm CLI；公共 npm 发布、实际安装修改和 Git 提交/推送不包含在本规格的自动授权中。

## Testing Decisions

- 主要测试边界是公开 CLI：使用临时插件根目录和独立操作存储，通过真实命令验证检测、准备、应用、状态、恢复及中断恢复。断言退出码、JSON、可见诊断和文件结果，不依赖内部函数名或日志顺序。
- 另保留一个纯源码分析边界，用精简样例验证结构兼容性和局部变换。该边界属于产品真实职责，不为测试暴露 AST 遍历器、绑定表或匹配器内部状态。
- 结构样例覆盖变量/函数改名、引号/空白/压缩差异、作用域遮蔽、无关相似代码、多个完整候选、请求来源变化、禁止语义改变、内联或拆分超出支持模式、无效语法及已补丁状态。
- 变换测试验证目标表达式以外内容保持不变，其他 feature 字段和原始响应保留，agent 的本地消费结果为 false，输出可解析。测试执行自带精简样例，不执行提取的真实应用 bundle。
- 文件与事务测试覆盖准备失败、全部预检、重复应用/恢复、混合已知状态、prepare 后修改、备份或方案被篡改、并发锁、写失败、回滚失败、强制终止窗口、恢复中再次终止及外部修改冲突。
- 进程检查使用受控环境输入或测试替身验证允许和拒绝行为；不要求 CI 安装或启动真实 Codex，不终止用户进程。
- CLI 契约测试验证目标选择、不同版本并存、人类可读及 JSON 输出、错误分类与退出码；打包验收在临时目录安装 npm pack 产物并执行命令。
- 现有 Python 测试可借鉴往返、幂等、外部修改保护和写失败回滚的行为案例，但新的测试不得继承对某个本机插件版本的依赖，也不得因缺少该安装而跳过核心验证。
- CI 在未安装 Codex 的环境执行类型检查、静态检查、测试和构建。真实本机样本只作为额外的只读结构验证，记录样本身份和结果，不进入发布包。
- 分别记录自动化验证、真实工件结构兼容性、真实 Codex 加载与网站工具操作。后两项缺乏实测证据时明确标记未验证。

- 任务面板、MCP App 界面、通用扩展宿主及 CDP/Electron 运行时注入。
- Electron 主进程的侧栏评论模式补丁、应用归档重打包和应用签名修改。

- 自动结束 Codex 及相关工具进程。
- 自动适配未知结构、自动跟随更新重新应用补丁。
- 公共 npm 发布、对已安装插件的实际应用、Git 提交/推送。
- 将真实应用 bundle、用户备份或本机方案作为测试 fixture 或发布资产。

## Further Notes

本规格源于用户已确认的十一项设计选择及完整设计确认。站点状态限制、插件文件补丁和结构兼容性使用项目已约定的领域术语。

截至规格整理时，现有工具只生成过补丁副本并完成文件级测试，没有修改真实安装。真实插件加载、宿主完整性检查、更新覆盖以及实际网站操作均未验证。

兼容性诊断应保留“结构足以适配”与“真实运行已生效”的区别。目标字段、消费关系或禁止语义发生变化时，正确结果是拒绝适配并提供证据，而不是尽量完成写入。
