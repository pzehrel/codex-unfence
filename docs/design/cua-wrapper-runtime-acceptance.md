## 执行前确认

- 明确允许修改的安装、已审阅准备目录及私有操作存储；接受封存资源不一致可能影响加载。
- 明确宿主退出／启动由谁操作。工具检查相关进程，不主动终止进程。
- 选择允许测试的 URL 和动作，明确是否涉及业务写操作。
- 明确结束后立即恢复还是保留补丁；保留准备目录、操作存储、备份与包外协调历史。

## 验收步骤

1. **核对身份与基线。** 记录版本、大小和摘要。确认选定站点原先的拒绝确由站点状态触发，其他拒绝不计为包装器成功或失败。
2. **退出宿主并应用。** 在维护窗口确认相关进程退出，完成备份、意图持久化和原子替换；核对工具状态及补丁摘要。失败先读取状态，不手工绕过锁。
3. **重新加载并观察。** 确认实际加载对应 CUA 路径。原链保留 inflight 和 24 小时缓存；文件变化不能证明进程采用补丁，旧缓存影响须单列。
4. **确认字段作用。** 原站点状态成功解析且 agent 严格为 true 时，当前消费链应收到副本中的 false，其他字段保持。访问成功不能单独证明字段改写；额外诊断须有明确范围。
5. **核对其他权限。** 仅在现成且获准的拒绝场景核对原行为，没有场景则标记未验证。
6. **恢复并独立核对。** 检查原文字节、目标目录布局、可信 restored 状态、未完成事务及严格签名，再确认宿主可用。未知内容或更新导致冲突时保留现场，不强写覆盖。

## 历史工具状态语义

固定配方的准备与操作脚本已移除，其命令不再可执行。当前安装、检查、卸载及中断处理见 [README](../../README.md)。历史准备目录、存储及真实备份仍应保留；它们不是当前产品的自动接管入口。

当时 status 的 `state: original` 表示当前字节为原始内容；只有可信、实际完成的恢复历史才另有 `action: restored`。首次未应用或空操作 restore 不产生该标记。`state: tool-applied` 表示当时工具的可信应用状态，外部身份变化返回冲突。

当时 recover 回到未完成操作开始前的状态，与普通 restore 返回原文不同；恢复依赖所属存储内保存并重新验证的方案。
