# Spec：指定真实浏览器插件的结构适配与静态验收

已发布：[GitHub Spec #9](https://github.com/pzehrel/codex-browser-liberation-patch/issues/9)，标签 `ready-for-agent`。

## Problem Statement

现有 macOS CLI 已具备插件发现、可审阅方案、可信状态、事务应用、恢复及中断回滚，但结构分析仅能证明简化的合成代码。指定真实插件包含延迟初始化、拆分 URL 构造、类表达式、缓存及进行中请求复用，无法通过当前有限模式；全源码调用闭包还会因无关 bundle 代码而拒绝。

用户因此仍不能为当前保留的真实 browser/chrome 工件生成经结构证明的插件文件补丁方案。大量合成测试通过也不能回答“这两份实际文件是否适配”。用户需要真实样本作为明确交付门槛，同时知道静态兼容、文件变换和真实运行有效性分别得到哪些证据。

## Solution

扩展现有有限结构分析，证明影响站点状态判断的相关代码链，允许与该链无关的 bundle 代码存在。首批验收针对版本 `26.1013.31256` 的 browser/chrome 两份实际工件；分别完成只读检测和本地方案生成，输出结构证据、变换区间及前后哈希，保持安装文件不变。

证明覆盖相关初始化、请求来源、响应解析、agent 严格禁止判定、缓存及实际 policy 消费入口。相关关联无法证明、存在无法排除的动态修改或目标不唯一时，明确拒绝。变换仍只在目标消费点构造响应副本，将 agent 标志固定为 false；请求、原对象、其他字段、缓存和异常处理保持原有流程。

CI 使用自行编写的可分发合成样例。本地真实样本验收是独立且必须通过的交付门槛；真实 Codex 加载、宿主完整性和网站操作继续标记未验证。

## User Stories

1. 作为用户，我希望检测当前真实 browser 插件的结构兼容性，以便知道工具是否能处理实际安装中的文件。
2. 作为用户，我希望独立检测同版本的 chrome 插件，以便不会因两份源码相同就遗漏另一目标的路径与身份验收。
3. 作为用户，我希望首批验收明确限定版本 `26.1013.31256`，以便交付结论有可核对的样本范围。
4. 作为用户，我希望版本和完整文件哈希仅记录身份，以便结构仍兼容的改名、格式变化不会被版本白名单阻止。
5. 作为用户，我希望无关 bundle 代码不会自动造成拒绝，以便分析器能适配包含其他正常功能的真实插件。
6. 作为用户，我希望相关初始化器及其调用顺序得到证明，以便不会把尚未初始化的常量当成已知值。
7. 作为用户，我希望条件初始化、重赋值和无法证明的初始化关联被拒绝，以便检测不会猜测运行时值。
8. 作为用户，我希望拆分的 URL 构造及输入处理得到验证，以便补丁仍针对站点状态请求。
9. 作为用户，我希望请求来源、GET 参数和运输包装的关联得到证明，以便无关请求不会被误改。
10. 作为用户，我希望 HTTP 检查、JSON 解析与响应绑定得到验证，以便变换不会删请求或吞掉原本的错误。
11. 作为用户，我希望 agent 严格为 true 才禁止的语义得到证明，以便 truthy、取反或其他字段不会误命中。
12. 作为用户，我希望证明实际 checkUrl 到 policy 的消费入口，以便只定位未被调用的方法不能冒充完整适配。
13. 作为用户，我希望类表达式、实例与方法接收者的关系得到证明，以便继承覆盖、借用调用或提取方法不会被错误认作同一链。
14. 作为用户，我希望相关类、实例、判定函数或配置逃逸到未知外部调用时被拒绝，以便信任边界清楚。
15. 作为用户，我希望当前文件中能影响相关链的反射修改、原型替换与别名写入得到检查，以便不会重现已发现的误接受问题。
16. 作为用户，我希望工具明确其标准宿主能力和 Node 模块假设，以便不会把结构兼容性误解为整个环境的安全证明。
17. 作为用户，我希望新响应只在目标消费点被复制并修改，以便原始响应和其他消费者保持原有数据。
18. 作为用户，我希望补丁以外的源码字节保持不变，以便审阅者能精确核对改动范围。
19. 作为用户，我希望其他 feature 字段、顶层字段及用户授权和企业策略判断保持原有行为，以便补丁作用范围不扩大。
20. 作为用户，我希望缓存命中、过期和进行中请求复用保留原有语义，以便结构适配不会顺带重写请求调度。
21. 作为用户，我希望缓存命中时仍先发起请求的现有行为得到保留，以便测试不会用更简单但不等价的缓存替代真实流程。
22. 作为用户，我希望原有异常返回和错误处理保持不变，以便本次适配不会通过请求失败触发放行。
23. 作为用户，我希望说明旧缓存的禁止结果不会因磁盘副本改变立即消失，以便不会把局部变换误认为即时运行生效。
24. 作为用户，我希望通过现有 prepare 明确选择两份真实工件并生成可审阅方案，以便不用另走一次性字符串替换脚本。
25. 作为用户，我希望方案保存结构证据、变换区间、原始及补丁哈希，以便检查内容和后续校验有依据。
26. 作为用户，我希望新模式生成的方案仍能被重新分析和推导校验，以便方案加载不能只相信清单自报的哈希。
27. 作为用户，我希望检测和准备保持安装内容不变，以便本轮静态验收不会隐式应用补丁。
28. 作为用户，我希望指定真实样本缺失或变化时验收失败，以便工具不会换样本、跳过检查后仍宣称完成。
29. 作为维护者，我希望自动化使用自造精简正反样例，以便未安装 Codex 的 CI 也能验证新增模式。
30. 作为维护者，我希望样例覆盖完整初始化、请求、缓存和消费关系，以便合成测试不再只验证比真实场景简单得多的链。
31. 作为维护者，我希望改名、引号、空白、压缩及非 ASCII 前缀变化有回归，以便结构识别和源码区间不依赖特定文本布局。
32. 作为维护者，我希望保留反射别名、动态接收者、遮蔽、请求来源改变和多候选的负例，以便新模式不通过放松验证获得兼容。
33. 作为维护者，我希望通过公开 CLI 和既有纯源码边界验证行为，以便测试不依赖内部遍历器或绑定表。
34. 作为维护者，我希望安装后的 npm 产物能处理新合成模式，以便源码运行成功能够兑现为可交付命令。
35. 作为维护者，我希望真实源码、备份和补丁副本不进入 Git 或 npm 包，以便分发不携带专有工件或本机状态。
36. 作为用户，我希望完成记录分别列出合成自动化、真实结构及文件变换、真实运行证据，以便每种成功声明都有实际依据。

## Implementation Decisions

- 沿用 Node.js + TypeScript、macOS 支持范围以及现有安装发现、纯源码分析、方案、事务和命令入口的职责边界。本轮扩展分析和静态验收能力，不重建事务层。
- 实现明确且有限的真实 bundle 结构模式，不做任意 JavaScript 的通用数据流分析，不依赖压缩函数名或局部变量名准入。
- 以相关站点状态代码链作为证明边界，遵循已确认的 ADR 0002。允许无关调用、导入及属性写入，但必须检查当前文件中可能影响相关链的修改与逃逸；不能以“位于别处”代替无关性证明。
- 信任宿主标准内建能力、约定运行时请求接口、JSON 解析及 Node 标准模块按约定工作。不递归审计所有依赖，不承诺抵御宿主预先篡改能力或外部模块中的任意恶意行为。
- 相关类、实例、判定函数或可变配置传给无法证明行为的外部调用时拒绝。相关函数替换、原型变更、反射别名写入、接收者不明或无法排除的动态修改仍须拒绝；这些约束不能因无关 bundle 代码被允许而消失。
- 初始化证明覆盖一次性延迟 helper 的有限语义、相关常量的唯一赋值及使用前初始化关系。仅看到一次赋值或源码行顺序不够；需要在信任边界内证明相关依赖和调用关系，无法证明时输出具体诊断。初始化异常不被当成成功到达后续消费。
- 请求来源证明覆盖输入 URL 处理、拆分 builder、站点状态 endpoint、site_url 与请求上下文参数的关联，保持协议和本地地址处理、URL 字段保留及过滤的原有行为。
- 验证运输包装对相应 runtime.fetch 的 receiver 和参数传递、GET 请求、同一 HTTP 对象的成功检查、同一响应的 JSON 解析及 JSON binding 的判定消费。
- 验证对象 guard、feature_status 读取、agent key 和严格 true 禁止语义。字段语义属于结构证据，版本、哈希、压缩名称不属于兼容性证据。
- 验证实际类表达式、构造和状态字段的相关关系，覆盖 checkUrl 返回结果到真实 policy blocked 判断的消费链。孤立的 fetchBlocked 或未被实际消费的 throwIfBlocksUrl 不足以宣布兼容。
- 缓存及进行中请求复用属于需要识别和保留的有限控制流：包括先启动新请求、旧缓存命中、旧 promise 复用、新结果记录、过期判断、清理关系和相应异常分支。缓存命中后的新请求错误处理与实际入口的异常返回也必须保留。
- AST 用于验证和定位，仍只替换唯一目标响应实参的源码区间，构造局部浅副本并令嵌套 agent 为 false；保持原判定器调用和其他字节，输出再次解析。不得全 bundle 重打印或改通用判定器。
- 新增模式及证据必须具有可区分的模式身份，并与现有方案的格式校验、重新分析、变换推导和状态诊断协调。保留既有已支持模式及可信方案的可验证行为，不把不认识的模式视为可应用。具体内部拆分由实现确定。
- 通过现有 detect 和 prepare 提供能力，沿用明确目标选择、统一 human/JSON 模型、退出码、无覆盖方案生成和完整性校验。不以多个候选中挑第一个或字符串替换作为回退。
- 首批本地验收分别针对 `26.1013.31256` browser/chrome 的规范工件。即使两份字节相同，也分别验证身份、发现结果、结构证据、方案生成和安装内容未变化；不使用 latest 推断运行版本。
- 样本哈希作为本轮验收身份基线，生产结构分析不以它为白名单。指定样本缺失或身份基线变化时，本次真实验收失败并报告，重新确认样本后方可更新验收依据；不自动跟随更新。
- 本地真实验收只将源码当作数据解析并生成隔离副本，不 import 或执行真实 bundle。副本、原文备份及本机方案存于 Git/npm 排除的本地位置；可公开记录非源码证据和验收结论。
- 沿用既有测试进程隔离、统一检查入口和发布包精确白名单。新增样例和本机验收资产不能混入发布包；新分析运行代码若需要分发，应同步精确清单和安装产物验证。
- 文件级成功、结构兼容性与运行时状态继续分开表达。真实宿主加载、模块重载、缓存清除、完整性接受和网站操作没有本轮实测证据时，保持 not-verified。

## Testing Decisions

- 已在设计访谈中确认：CI 跑可分发合成样例，本地单独验收指定真实样本。沿用两个已有测试边界：主要通过公开 CLI 验证检测、方案及诊断；纯源码分析/变换边界用于有限结构及局部语义。真实验收复用公开 CLI，不新增内部 AST 测试入口。
- 好的测试断言用户可见结果：兼容或拒绝、诊断与退出码、证据、目标选择、生成工件和实际文件内容。测试不依赖 AST 遍历器、绑定表、私有 matcher 名称或日志顺序。
- 合成 fixture 自行编写，保持真实相关结构关系而不复制真实 bundle。既有合成改名、格式、源码区间、响应副本、外部修改保护、事务和安装包验收是先例；新增模式须补完整链，而不只补孤立语法片段。
- 正例覆盖延迟初始化、拆分 URL、带 guard 的运输函数、类表达式和实际 policy 消费，以及包含无关调用/导入/属性操作的 bundle 环境。标准接口假设应在样例说明及用户文档中明确。
- 负例覆盖初始化缺失、条件初始化、错误调用顺序、重赋值、遮蔽、请求 endpoint/site_url 来源变化、响应 binding 替换、agent 语义变化、相关对象逃逸、反射/原型/别名修改、子类覆盖、借用调用和多个完整候选。超出新增有限模式的控制流明确拒绝。
- 对结构相同的函数/变量/方法改名、引号/空白/压缩变化保持识别；验证 BOM、CRLF、中文及非 BMP 前缀下 UTF-16 区间与 UTF-8 字节保持正确。
- 仅执行自造样例验证局部副本：agent true/false/其他值、缺字段、原响应及其他字段保留、请求参数与次数、HTTP/JSON 错误、后续授权 sentinel。真实 bundle 从不执行。
- 用合成时钟、请求和 promise 结果验证缓存命中、过期、新旧 inflight 关系及清理、先启动请求后复用旧值、丢弃请求的错误处理、入口异常返回。对照补丁前后，除目标新响应判定外，相关控制流和可见副作用保持一致。
- CLI 合成测试使用临时插件根目录、隔离 HOME/状态目录和既有子进程入口，覆盖 browser/chrome、多版本、显式目标、prepare、方案重新加载/重推导及篡改拒绝。未知形态不得声明是本工具应用。
- 既有可信方案、事务生命周期、锁发布中断、历史版本删除和外部修改保护回归继续通过；若不涉及这些行为，不为本轮重复设计新的事务内部测试 seam。
- 对本地打包并离线安装的 npm 产物执行新增合成模式的 detect/prepare，检查证据、方案和退出契约，保证源码能力实际分发；验证发布清单继续排除真实工件、方案、备份和本机状态。
- 无 Codex 的 CI 使用统一检查入口运行类型检查、静态检查、构建及全部合成测试，核心测试不因缺少真实安装而跳过。真实验收不伪装成可跳过的核心测试。
- 本地真实验收必须分别完成两份指定工件的存在性和身份基线核对、detect 兼容结果、唯一链结构证据、prepare 成功、原文/补丁哈希、唯一变换区间、区间外字节一致、输出语法解析成功，以及操作前后安装文件未变化的确认。
- 真实样本缺失、变化、不兼容、多候选或方案生成失败均使真实验收失败，不静默换版本、不用合成结果代替。验收记录明确执行日期、样本身份、使用的工具构建及结果；记录身份不代表已证明运行中的版本。
- 完成记录分别列出合成自动化、真实结构及静态文件变换、真实运行证据。前两项必须实际通过；第三项本轮明确未验证。

## Out of Scope

- 对任意 Codex 版本、任意打包器或任意 JavaScript 结构的通用支持。
- 以版本号或整文件哈希白名单替代结构兼容性判断。
- 递归审计全部依赖、整个宿主的安全证明，或抵御标准宿主能力被预先恶意篡改的保证。
- 无法证明时继续适配、宽松字符串替换、自动选择歧义目标、自动跟随更新重新应用。
- 执行或 import 真实 bundle，实际修改已安装插件、启动或重启真实 Codex、终止用户进程。
- 真实宿主模块加载、缓存清除、完整性行为和网站工具操作验证；这些需要后续独立范围及授权。
- 侧栏评论模式、主应用归档、签名修改、运行时注入、网络代理或服务端响应改写。
- 取消用户拒绝、企业策略、Guardian/Auto-review、协议限制或 Full CDP 权限。
- 改写缓存策略、改变异常处理或借请求失败触发放行。
- 重建既有事务层、全局代理编排技能改进、Windows/Linux 正式产品支持。
- 将真实源码、提取工件、备份或补丁副本提交到 Git 或纳入 npm 分发。
- 公共 npm 发布、Git 提交或推送；调用本技能仅授权规格整理及按要求发布工作项，不授权这些操作。

## Further Notes

本规格来自 2026-10-17 已完成的设计访谈。Q1–Q8 逐项接受，Q9 最终范围确认；结构兼容性继续沿用 ADR 0001，相关链及依赖信任边界采用 ADR 0002。

当日只读核验的两份 `26.1013.31256` 工件均为 **1,462,840 bytes**，SHA-256 为 **`67f78205a36436e511de3687c104d10d39d91784593bb885883439ef8f2236bd`**。两份源码逐字节相同，但实际文件身份独立；旧版本 `26.1007.71326` 已不在默认缓存中。该记录是指定真实验收的身份基线，不是生产准入白名单，也不能证明正在运行的版本。

只读检查已发现候选响应消费点，但当前分析器仍返回 incompatible。定位候选、字节相同或历史测试通过均不构成本规格的完成证据。本规格生成时尚未修改分析器、生成真实补丁副本或执行真实运行验证。

本轮设计文档及 ADR 尚未提交。规格发布不表示实现已开始，也不表示代码或真实工件已上传。
