## 已查明的事实

指定 browser/chrome 的站点状态相关标准能力可被同文件中的 ZXing Wasm 句柄桥访问。句柄表会保留全局对象，桥支持动态读取、调用和构造；实际资源导入对应桥函数。模块初始化和后续条码读取都可能进入该桥，没有隔离 realm 或证明其不可达的证据。

实际内部初始化路径读取同目录 zxing_reader.wasm，并传入仅有 wasmBinary 自有属性的新普通对象。读取失败会尝试另一依赖路径，当前 fallback 不存在。没有发现显式提供 instantiateWasm 的调用者，但普通对象的继承查找以及初始化 hooks 仍需证明。

两份实测资源均为 1,065,866 bytes，SHA-256 为 0e8d688d71932ebb6b8b33f700d43d3cb997f59ed9cab3c05102d7f10288a392。该摘要仅标识本次观察到的依赖，不证明其语义、来源或安全。数据解析未执行、编译或实例化 Wasm；没有完成资源语义审计或可复现构建核验。

## 需要明确批准的新增假设

仅对独立批准并有证据绑定的这份 ZXing reader 依赖，信任其通过经验证的加载器和导入桥执行初始化及图像解码时，在整个生命周期中：

- 不替换或修改相关宿主全局能力和原型；
- 不修改站点状态请求、判定、类、实例及配置；
- 不安装未来触发上述修改的延迟效果。

这是对该依赖的语义信任，不是静态调查已证明的事实。动态全局访问依然存在；采用本提案即把这一非干扰义务交给批准的组件契约。Node 标准模块信任不自动包含此假设。

## 最小实现范围

1. 为批准的依赖建立明确契约版本和身份记录。资源摘要绑定该次批准及变更检测，不作为站点状态结构兼容性的替代依据；不泛化到任意 ZXing、Wasm、生成器代码或同名文件。
2. 有限结构证明关联资源加载器、字节来源、初始化调用、实际导入表、桥操作和解码调用点。新普通对象的自有键、继承属性及 hooks 缺失须在现有标准宿主假设和当前文件影响检查内得到证明；无法证明则拒绝。
3. 只将契约覆盖的依赖消费效果作为已信任条件；其余直接写、别名、反射、原型、回调、相关对象逃逸检查继续生效，包括加载包装内部。不能跳过整个函数或代码区间。
4. 纯源码分析/变换不隐式访问文件系统。为依赖证据设计显式、版本化的附加输入；缺少证据继续拒绝。证据不能是调用方任意提供一个 trusted 布尔值。既有调用和旧模式行为保持兼容。
5. CLI 新增受限的只读依赖解析和身份/并发变更核验。本次只支持明确相邻资源；fallback、未知资源、额外回调/hook、新调用点、导入桥变化或相关修改均拒绝。标准文件系统和稳定字节假设须明确说明，磁盘快照不证明未来宿主实际加载的字节。
6. 方案绑定依赖身份、契约版本、加载器与桥结构证据；加载和变换重推导重新核对，不能信任重算哈希后的清单自报。明确历史方案内容验证与当前依赖检查的职责，避免删除历史安装后破坏其他可信事务。应用时依赖变更也须拒绝；不在本次真实安装执行 apply。
7. 合成测试覆盖有效契约、无证据、未知或变更资源、错误关联、回调/原型/别名修改和重新哈希篡改。测试仍以公开 CLI 和纯源码边界进行，不新增内部 AST seam，不执行真实资源。离线 npm 安装验收覆盖新增代码。
8. 两份真实工件仍须分别完成原定 detect/prepare、结构证据、哈希、区间外字节、方案重验和安装未变核验；额外记录依赖身份与采用的契约。任何失败不能跳过后宣称完成。

## 风险与不变的限制

若批准的依赖实际违反非干扰契约，源码结构证明仍可能报告兼容。因此报告必须区分已证明的结构与已信任的依赖语义，不能声称整个环境已安全。

本提案不授权真实 bundle/Wasm 执行、编译、宿主启动、安装写入、公共发布或推送；运行时依旧 not-verified。资源来源、复现构建或深度 Wasm 语义审计不是已完成证据。
