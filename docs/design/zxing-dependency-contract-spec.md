# 规格 9 增补：特定 ZXing 依赖契约与证据

日期：2026-10-17。来源：用户已批准 `zxing-dependency-boundary-proposal.md` 中的特定语义契约与显式依赖证据接口。本文与原规格共同生效；原规格的真实验收门槛、局部变换和禁止执行/安装写入等限制继续成立。

## 问题及决定

当前真实样本因 ZXing 句柄桥将标准宿主能力交给不透明资源而拒绝。只读调查已定位资源、加载器、桥和实际初始化输入，但未证明资源语义非干扰。按 ADR 0003，对明确批准并有证据绑定的这份依赖接受生命周期非干扰契约；其余相关链结构、影响检查及未知形态拒绝保持。

实测批准资源为两份指定 browser/chrome 的相邻 zxing_reader.wasm，各 1,065,866 bytes，SHA-256 0e8d688d71932ebb6b8b33f700d43d3cb997f59ed9cab3c05102d7f10288a392。摘要只把契约批准绑定到确定字节，不能证明其行为，也不是整个源码结构的准入白名单。报告须明确区分结构证据、已信任的依赖语义、文件身份和未验证运行效果。

## 实现及测试约束

- 保持有限结构证明。关联实际资源路径及读取流程、复制字节、初始化配置、导入表/桥行为、实际调用点与生命周期；不以压缩名称匹配，不按整源码哈希或代码区间豁免整个包装。仅对契约覆盖的特定依赖消费效果接受语义假设，其余当前文件可见修改和逃逸照常检查。
- 证明新普通对象的配置仅包含允许的资源输入；继承属性查找和初始化 hooks 也须在标准 Object.prototype 假设及当前文件影响检查下排除。任意替换 instantiateWasm、额外 hooks、未知资源、fallback、额外桥导入或调用点变化均拒绝。
- 显式扩展既有纯源码分析/变换边界的依赖证据输入，不增加隐式文件读取或内部 AST 测试入口。无证据继续拒绝；证据必须经过契约、资源身份和结构关系验证，不能由任意 trusted 布尔值自报批准。既有无该依赖的调用及旧模式方案保持可验证。
- CLI 在已选目标范围内受限地只读读取依赖，核对规范路径、普通文件身份、别名/符号链接及并发变化。支持明确的相邻资源路径，fallback 和无法确认的运行时字节来源拒绝；说明静态快照与标准文件系统假设不能证明未来宿主实际加载字节。
- 方案持久化契约版本、资源身份和加载器/桥证据，并在加载及补丁推导时重验。不可只相信清单中的摘要或重新哈希后的证据。历史内容证明与 live 源码/依赖核验分离，删除旧版本不得破坏其他操作。应用实际依赖变更时拒绝；本轮仅以临时合成安装验证应用行为。
- 自造可分发正反样例验证接口证据、完整结构与有限契约范围、未知/修改资源、错误关联、fallback、回调/原型/别名改动和方案篡改。CI 不需要真实 Codex；真实资源不能复制到夹具、Git 或 npm。安装后的离线 npm CLI 验证新增能力及精确发布清单。
- 必须实际完成原工单 14 的两份真实工件 detect/prepare 验收，并额外记录依赖身份和契约证据。原文、资源与安装身份前后保持不变；本地副本仅在排除位置；无真实 bundle/Wasm 执行、编译、实例化或宿主启动。
