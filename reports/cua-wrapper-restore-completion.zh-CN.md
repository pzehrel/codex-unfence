# CUA 恢复收尾实现记录

2026-10-20。用户在真实验收后调用 `/implement`，要求解决恢复原文后租约残留导致签名失败的问题。本轮只修改仓库代码、文档并运行合成验证，没有再次修改真实安装、运行真实插件、推送或发布。

## 结果与范围

新 CUA apply／restore／recover 的目标协调记录和替换暂存均位于操作系统账户 home 下 `.codex-browser-patch/target-leases/<规范父目录 SHA-256>/`。目录 0700，租约记录 0600；协调位置不受 `HOME`／XDG／`--store`、目标 inode 或准入方案影响。正常恢复不在应用内留下租约，替换前 SIGKILL 也不在应用内留下暂存文件。包外历史保留，操作存储、准备副本及备份不删除。

采用保留包外历史，而非在线删除目标旁历史：删除 CAS 后继链会让已经读取旧后继位置的等待进程发布到失去根节点的分支。所有当前引擎写入者先获取存储租约和包外父目录协调租约；结构方案随后仍获取旧目标旁租约，保持旧 journal、来源与恢复契约。不同准入方案遇到对方历史时保守拒绝，不隐含降级验证。

旧版目标旁锁、孤立后继、`.publish-` 或本工具临时资源返回 `LEGACY_TARGET_ARTIFACTS`，普通写入与恢复均不自动删除。用户需要独立离线维护；不提供 force／skip。旧二进制和外部写入者不受新协议保证，不应与当前工具并发运行。

CUA 替换使用从包外暂存到目标的原子 rename，并同步源、目标目录。跨文件系统不支持时失败并保留已有事务保护，不退回复制。暂存中断遗留内容位于私有协调目录，仍需保留，不当作应用资源或已验证归档删除。

## 验证

沿用公开 CLI、合成临时文件系统、共享隔离启动器。测试预加载仅在 OS 账户 home、进程、摘要和文件系统边界建模，不进入生产参数或 npm 包。

- 原目录布局回归先失败：应用后多出 `.codex-browser-patch.lock` 及释放后继；迁移协调记录后通过。
- 替换前中断回归先失败：旧暂存留在目标旁使 recover 被残留保护阻断；移出应用后通过。
- 新回归覆盖重复恢复无资源新增、历史保留、旧版及孤立残留拒绝、包外首次／后继／释放发布中断、等待者不绕过另一存储的 pending 事务、获取协调后重新检查目标残留、共享结构／CUA 父目录排他，以及协调目录别名、权限和记录篡改拒绝。
- 首轮统一检查 358/359，唯一失败是测试 fixture 加载时创建 home 破坏只读 detect 的零写入断言；改为 OS 账户查询时才创建，定向验证通过。
- Standards 初审提出两项判断性意见：HOME／XDG 测试未真实改变子进程环境，以及协调策略选择重复。已修正并独立复核关闭，最终 Standards 为 0 项。
- 修正只读 fixture 后统一检查 359/359 通过。Spec 独立审查另复现两项 P2：协调命名空间可能污染准备目录、status 漏报孤立旧残留。均已通过公开 CLI 红绿回归修复，分别增加重合／双向包含写前拒绝与 status 只读冲突诊断。原 Spec 审查者额外验证目录子路径、父路径、相邻前缀及 pending 时残留场景，确认两项关闭，无新增阻断项。最终统一检查 `npm run check -- --base 20bb0a931a438092ed6d463fc1be0727ebabbd9e` 通过：类型、lint、构建及 360/360 测试（含已安装 npm 产物回归），0 失败、0 跳过，测试耗时 134,609 ms。Standards 最终 0 项，Spec 最终 0 项。
